# Languages and translation contributions

English is the canonical source and fallback language. The card includes 24
complete language packs, matching the language set used by
[DESLOC Lock Card](https://github.com/ha-homelab/ha-desloc-card): English, Arabic,
Bengali, Czech, German, Spanish, Persian, French, Hebrew, Hindi, Indonesian,
Italian, Japanese, Korean, Dutch, Polish, Portuguese, Russian, Thai, Turkish,
Ukrainian, Vietnamese, Simplified Chinese and Traditional Chinese.

## Automatic selection

Leave `language` out of the card configuration, or set `language: auto`.
The card follows the Home Assistant profile language and redraws when that
profile changes. An English profile displays the interface in English.

Selection uses the same order as DESLOC:

1. An explicit per-card `language` override, unless it is `auto`.
2. `hass.locale.language` from the Home Assistant profile.
3. The legacy `hass.language` property.
4. English when no language is supplied or the selected language is unsupported.

An unsupported explicit override falls back to English; it does not silently
select a different language from the profile. Browser language is used only by
the card-picker description, before HA supplies its profile. The placeholder
configuration omits literal names so defaults follow the eventual HA profile. It does not override the language of an installed card.

Regional tags resolve to the corresponding language pack. Examples: `pt-BR` →
Portuguese, `fr-CA` → French, `zh` / `zh-CN` / `zh-SG` → Simplified Chinese,
`zh-TW` / `zh-HK` / `zh-MO` → Traditional Chinese. An explicit `Hans` script takes
precedence over a region (`zh-Hans-TW` remains Simplified Chinese). Underscores
and case differences are normalized. Codes and native names are listed in
[`locales/index.json`](../locales/index.json).

For an independent override on one card:

```yaml
type: custom:ha-jbd-bms-card
language: fr
batteries:
  - soc: sensor.my_battery_soc
    voltage: sensor.my_battery_voltage
    cells:
      - sensor.my_battery_cell_1
      - sensor.my_battery_cell_2
```

Replace the illustrative entity IDs with real entities. To force English, use
`language: en`. To return to profile detection, remove that line or use `auto`.

## Translated surface and literal data

Translations cover default titles and battery names, measurement labels,
availability and missing-data states, spread captions, freshness limitations,
configuration validation, more-info accessibility text and the picker description.
Product names remain literal, including **JBD Battery & Cell Card**, Home Assistant
and Victron. User-provided titles, battery names, subtitles, cell names, entity IDs,
values and physical units are not translated or renamed.

Arabic, Persian and Hebrew set the element's `dir` to `rtl`. Logical margins and
cell bars follow that direction; numeric telemetry and its units are isolated
left-to-right. Locale changes never alter a measurement, map a different entity,
issue a service call, or change availability rules. The card remains read-only.

Every pack is embedded in the **same JavaScript module**. No language resource,
translation service, CDN request, browser storage or new HACS resource is required.
Text and interpolated user values are escaped before rendering; interpolation
runs once, so braces inside a battery name remain literal text.

## Edit or add a translation

1. Edit `locales/<code>.json`; `locales/en.json` defines the canonical keys.
2. Keep the same keys, nonempty string values and named placeholders. Do not
   translate YAML property names, entity IDs or placeholders such as `{field}`.
3. Preserve the distinction between available HA entities and fresh physical
   measurements. “Low spread” must not imply that the battery is healthy or safe.
4. For a new pack, add its native name and `ltr`/`rtl` direction to the index, then
   update the supported-language test.
5. Regenerate and verify the bundle, committing both JSON sources and the root JS:

```bash
npm run i18n
npm run check
npm test
npm run build
node scripts/check-package.mjs
```

The generator rejects missing/extra keys, empty text and mismatched placeholders.
CI checks that the checked-in bundle exactly matches the source dictionaries.
Runtime tests cover every language, direction, regional fallback, profile changes,
per-card overrides, localized errors, literal names and accessible more-info labels.
These tests verify the integration and data contract, not native-speaker wording;
translation corrections are welcome with a fictional example and no private data.

The [synthetic demo](../demo/index.html) provides separate HA-profile and card
language selectors so automatic selection and overrides can be inspected without
a live Home Assistant connection. It starts with an English profile and automatic
card language selection.
